Claude Code 安装配置完整教程

从零到跑通第一个任务。四步能做完的事，卡住的从来不是第三步。

开始之前：只有一个硬性要求

Node.js 18 或更高。低于 18 会因为缺少内置 fetch 和较新的 ESM 支持而装不上，报错通常是 SyntaxError: Unexpected token 或 fetch is not defined。

# 先确认版本
node -v
npm -v

# 低于 18 就升级。用 nvm 最省事：
# macOS / Linux
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install 22 && nvm use 22

# Windows 用 nvm-windows 或直接装新版安装包

版本对了再往下。这一步跳过的人，后面所有报错都会被误判成"网络问题"。

第一步：安装

npm install -g @anthropic-ai/claude-code

# 验证是否装上
claude --version

装完提示 command not found / 不是内部或外部命令

不是安装失败，是 npm 的全局 bin 目录不在 PATH 里。

# 看全局安装路径
npm config get prefix

# macOS / Linux：把 /bin 加进 PATH
echo 'export PATH="$(npm config get prefix)/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# Windows： 本身就在 PATH 里（不是它的 bin）
# 用系统环境变量界面把 npm config get prefix 的输出加进去，然后重开终端

PowerShell 里改完 PATH 必须重开窗口才生效，当前窗口不会刷新。

第二步：拿一个 API Key

这一步取决于你用哪家的端点。三种常见来源：

来源特点适合
官方 anthropic.com最稳，需要海外支付方式有外币卡、对稳定性要求高
云厂商市场一张云账单搞定，能开票公司采购、要报销
中转网关人民币支付、国内直连个人开发、快速试

选哪个不影响下面的配置步骤——Claude Code 只认两个变量，端点填什么地址都行。

判断一个端点是否可用，最快的方法是不带 key 请求一次：

curl -s -o /dev/null -w '%{http_code}\n' https://你的端点/v1/models

# 返回 401 = 端点活着，只是需要鉴权（正常）
# 返回 404 = 路径不对或端点不存在
# 返回 200 = 这个端点不校验鉴权，谨慎使用

第三步：配置（这里最容易错）

Claude Code 读两个环境变量，名字必须一字不差：

变量填什么常见错误
ANTHROPIC_BASE_URL网关地址，末尾不带 /v1带了会拼成 /v1/v1/messages → 404
ANTHROPIC_AUTH_TOKEN你的 Key写成 ANTHROPIC_API_KEY → 401

写法一：当前会话临时生效（最快验证）

# macOS / Linux
export ANTHROPIC_BASE_URL="https://your-endpoint.example.com"
export ANTHROPIC_AUTH_TOKEN="你的Key"
claude

# Windows PowerShell
$env:ANTHROPIC_BASE_URL="https://your-endpoint.example.com"
$env:ANTHROPIC_AUTH_TOKEN="你的Key"
claude

# Windows CMD
set ANTHROPIC_BASE_URL=https://your-endpoint.example.com
set ANTHROPIC_AUTH_TOKEN=你的Key
claude

关掉终端就失效。适合先验证能不能通，别当长期方案。

写法二：写进 shell 配置（持久）

# zsh
echo 'export ANTHROPIC_BASE_URL="https://your-endpoint.example.com"' >> ~/.zshrc
echo 'export ANTHROPIC_AUTH_TOKEN="你的Key"' >> ~/.zshrc
source ~/.zshrc

# bash
echo 'export ANTHROPIC_BASE_URL="https://your-endpoint.example.com"' >> ~/.bashrc
echo 'export ANTHROPIC_AUTH_TOKEN="你的Key"' >> ~/.bashrc
source ~/.bashrc

写法三：写进配置文件（不污染 shell）

# ~/.claude/settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://your-endpoint.example.com",
    "ANTHROPIC_AUTH_TOKEN": "你的Key"
  }
}

这个方式的好处：不同项目可以用不同的 key，切换时不用改 shell。缺点是明文存在文件里，注意别提交进 git。

Windows 持久化

# setx 写进用户环境变量，对之后新开的窗口生效
setx ANTHROPIC_BASE_URL "https://your-endpoint.example.com"
setx ANTHROPIC_AUTH_TOKEN "你的Key"

# 当前窗口仍需手动设一次，或直接重开

第四步：验证跑通

不要一上来就跑大任务。按顺序做三个确认：

# 1. 变量是否真的进来了
echo $ANTHROPIC_BASE_URL       # PowerShell: $env:ANTHROPIC_BASE_URL
echo $ANTHROPIC_AUTH_TOKEN

# 2. 端点是否可达（不带 key 应返回 401）
curl -s -o /dev/null -w '%{http_code}\n' "$ANTHROPIC_BASE_URL/v1/models"

# 3. 启动交互界面
claude

第 3 步进去后问一句「用一句话解释这个项目的目录结构」，能正常返回就说明链路通了。

如果卡住，先看现象再查——不同报错对应完全不同的环节：

现象大概在哪一层先试这个
一直转圈，无报错DNS 或 TCPnslookup 你的端点域名
ECONNRESET / 握手失败TLS 被干扰curl -v 看是否停在 handshake
401变量名或 key变量名是不是 AUTH_TOKEN
404BASE_URL 多写了 /v1去掉末尾 /v1 再试
429速率限制看响应头 retry-after
model not found模型名不存在先 curl /v1/models 看清单

更细的分层定位见 连不上？四层排查，错误码逐条解释见 错误码对照。

七个最常见的卡点

1. 变量名写成 ANTHROPIC_API_KEY

这是最高频的一个。Claude Code 读的是 ANTHROPIC_AUTH_TOKEN，写错直接 401，而且报错信息不会告诉你变量名错了。

2. BASE_URL 末尾带 /v1

Claude Code 自己会拼 /v1/messages。你多写一个 /v1，实际请求变成 /v1/v1/messages → 404。

3. export 只对当前窗口生效

新开一个终端就没了。要持久化必须写进 ~/.zshrc / ~/.bashrc / setx / settings.json。

4. Node 版本低于 18

装不上或运行时报 fetch is not defined。用 node -v 确认，别用系统自带的旧版本。

5. npm 全局 bin 不在 PATH

装成功了但 claude 命令找不到。npm config get prefix 看路径，加进 PATH 后重开终端。

6. 公司代理拦了 TLS

浏览器能开网页不代表 curl / node 能连——很多企业代理只对浏览器放行。用 curl -v 单独测，不要用浏览器结果推断。

7. Key 有额度但模型没开通

返回 model not found 不是 key 的问题，是这个分组没开那个模型。先 curl /v1/models 拉清单，用清单里有的名字。

配置跑通之后

  • 想接别的工具（Cursor / Cline / Aider / Windsurf）：13 个工具的配置片段
  • 想控制成本、看清每笔花在哪：省 token 的七个开关 · 倍率不等于折扣

  • 担心代码数据流向：中转方能看到什么
  • 流式输出断断续续：SSE 排查
