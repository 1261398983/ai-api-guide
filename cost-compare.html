中转站 vs 官方 API

「0.08x」不等于官方价的 8%。四件事决定你实际付了多少。

先破一个误解

看到「官网价 0.08x」就以为省了 92%，是这类站点最常见的误读。

倍率乘的是站点自己定义的基准价，不是官方价。基准价高于官方价时，0.08x 可能只等于官方价的 20%–30%，而不是 8%。

唯一可靠的算法：拿同一个模型的官方单价，和站点后台的实际扣费，做同任务对比。

四件常被漏算的事

1. 汇率与结算货币

官方价以美元计，中转站多以人民币充值。人民币兑美元波动 3% 时，标称的折扣会跟着变。算成本时统一换算到一个币种。

2. 失败重试的二次计费

长上下文任务失败一次，重试等于把输入 token 再买一遍。如果站点稳定性是 95%，理论上你的有效成本要乘 1.05；稳定性 80% 就是 1.25。

3. 上下文重传

多轮对话每轮都要重发历史。这条在官方和中转都成立，但中转常没有 prompt caching 的折扣，长对话场景差距会放大。

4. 起充门槛与余额沉淀

「充 100 送 20」看着划算，但如果你的实际用量是每月 30，这笔钱要压三四个月。预付款的时间成本与损失风险都该计入。

对照公式

实际单位成本 =
    (官方单价 × 汇率 × 站点倍率)
  × (1 / 成功率)          # 重试损耗
  × (1 + 缓存缺失溢价)     # 长对话场景才有
  + 预付款年化资金成本

# 举例（假设值，请用你自己的实测替换）
官方 $15/M output tokens
汇率 7.2   倍率 0.22   成功率 97%   无缓存
→ 15 × 7.2 × 0.22 ÷ 0.97 ≈ 24.5 元 / M tokens

把你的真实数字代进去，和官方直连（含汇率、税费、外币卡手续费）比，才是可比的结论。

三种典型场景

场景月用量更划算的选择原因
个人学习 / 小工具< $10中转站官方有起充门槛与外币卡要求，中转可小额试
团队日常编码$50–300看稳定性单价差被重试损耗吃掉时，官方更稳
线上服务> $500官方或云市场需要 SLA、发票与配额保障，中转不具备

金额阈值会随汇率和站点定价变化，表里的数字是量级参考，不是精确分界。

怎么自己测一次

# 1. 用同一个 prompt、同一个模型，各跑 20 次
# 2. 记录：耗时、是否成功、返回的 usage 字段
# 3. 用站点后台的扣费金额 ÷ 实际 token 数，得到真实单价
# 4. 与官方价 × 汇率 对比

# 关键：一定要看 usage 里的 output_tokens，
# 有些站点会在返回里少报 token，但按未压缩的量扣费

这套测法 30 分钟能跑完，比看任何评测文都准。
