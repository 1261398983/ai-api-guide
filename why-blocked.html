排障指南 · 2026-10-24

Claude Code 在国内到底卡在哪

四个环节、四种报错，逐层定位比反复重装有效。

先分类：你看到的是哪一类错误

现象卡住的环节验证方式
一直转圈、无响应DNS 解析或 TCP 连接`curl -v` 看是否解析出 IP
`ECONNRESET` / 握手失败TLS 层被干扰`curl -v` 卡在 TLS handshake
`401 Unauthorized`鉴权变量写错检查变量名与 key 前缀
`403` / 要求验证出口 IP 或账号区域被风控换出口或换端点对比
`429`速率限制看返回头里的 retry-after

先分类再动手。90% 的「装不上」其实是 401，不是网络问题。

第一层：DNS

# 看解析结果与耗时
nslookup api.anthropic.com
dig api.anthropic.com +short

# 若返回 0.0.0.0 / 127.0.0.1 或超时，就是解析层出问题

DNS 污染的特征是「解析很快返回一个明显不对的 IP」，而不是超时。两种情况的处理方式不同：前者换 DNS 解析路径，后者查本机网络。

第二层：TLS 握手

# -v 会打印握手细节
curl -v --max-time 10 https://api.anthropic.com/v1/models

# 关注这几行：
#   Connected to ...            ← TCP 通了
#   TLS handshake, Client hello ← 开始握手
#   SSL connection using TLSv1.3 ← 握手成功
# 若停在 Client hello 后无下文，就是传输层被干扰

这一层的典型特征是TCP 能连上但 TLS 完不成。此时应用层重试没有意义，因为连接根本没建立。

第三层：鉴权变量

Claude Code 读的是 ANTHROPIC_AUTH_TOKEN，不是 ANTHROPIC_API_KEY。写错变量名不会报网络错误，而是直接 401。

# 正确写法（注意结尾不要带 /v1）
export ANTHROPIC_BASE_URL="https://你的端点"
export ANTHROPIC_AUTH_TOKEN="sk-你的密钥"
claude

# 自检：确认变量已生效
env | grep ANTHROPIC

另一个常见错误是 base URL 带上了 /v1：Anthropic 原生协议不需要，OpenAI 兼容协议才需要。

第四层：出口 IP 与账号区域

官方对注册地与常用出口有风控。即便网络通、key 对，也可能收到 403 或要求人机验证。判断方法：

# 看当前出口归属
curl -s https://ipinfo.io/json | head -20

# 对照：同一台机器换端点是否仍 403
curl -s -o /dev/null -w "%{http_code}\n" https://你的中转端点/v1/models

若官方 403 而中转端点 401（=需要 key，说明连通），问题就在账号/出口层，不在网络层。

四条可选路径

路径优点代价
官方 + 自建代理体验最接近官方，账号仍在自己手上需外币卡、需维护代理、仍需处理风控
官方 + 云厂商托管合规票据齐全贵，且可选模型受限
API 中转站无需外币卡、人民币按量、国内直连需信任运营方，模型与倍率要自己核
换工具零成本工作流要重学，生态不同

选哪条取决于你更在意「体验一致」还是「省事便宜」，没有普适答案。

如果选中转：最小配置

export ANTHROPIC_BASE_URL="https://api.97wl.cc"
export ANTHROPIC_AUTH_TOKEN="sk-你的密钥"
claude

# 先验证端点活着（不带 key 应返回 401，不是超时）
curl -s -o /dev/null -w "%{http_code}\n" https://api.97wl.cc/v1/models

返回 401 说明连通且鉴权生效；返回超时说明这个端点在你这儿不通，换路径比反复重装有用。

→ 打开注册页

注册时在推广码栏填渠道码可领额外额度；建议先充最小额度验证连通性。
