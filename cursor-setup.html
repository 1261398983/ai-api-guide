Cursor 接入自定义 API

填了 Base URL 却不生效，九成是搞错了功能边界，不是配置写错。

先搞清楚：哪些功能走你的 Key

这是最容易误解的地方。Cursor 不是一个"全部走同一个 API"的工具， 不同功能背后是不同的模型和计费方式。

功能走自定义 API？说明
Chat（侧边对话）✅ 走填了 key 就按你配置的端点走
Composer / Agent（多文件改代码）✅ 走同上，但要求模型支持工具调用
Tab 补全（行内灰字建议）❌ 不走Cursor 自家模型，本地推理，不读任何自定义端点
Cmd+K 行内编辑⚠️ 看模式订阅模式下走 Cursor 后端；自带 key 模式走你的端点
索引 / 代码库 embedding❌ 不走索引由 Cursor 服务端处理

所以「我填了 key，但 Tab 补全还是在用 Cursor 的额度」是正常现象，不是配置失败。

配置步骤

1. 打开模型设置

Cursor 设置 → Models（不同版本的入口文字略有差异，找 Models / 模型 这一项）。

2. 填入 Base URL 和 Key

OpenAI API Key        : 你的Key
Override OpenAI Base URL: https://your-endpoint.example.com/v1

# 如果你的端点同时支持 Anthropic 协议，也可以填：
Override Anthropic Base URL: https://your-endpoint.example.com
# 注意：Anthropic 协议的地址不带 /v1

OpenAI 协议带 /v1，Anthropic 协议不带。填反了会 404。

3. 添加端点实际支持的模型

Cursor 内置的模型名未必和你的端点一致。先拉清单：

curl -s "https://your-endpoint.example.com/v1/models" -H "Authorization: Bearer 你的Key" \
  | head -60

把返回里你要用的名字，逐个加到 Cursor 的模型列表里。名字必须一字不差， 包括版本后缀。

4. 关掉用不上的内置模型

Cursor 会默认尝试一堆模型。端点不提供的那些会不断报错，把列表里不需要的关掉， 能减少无谓的失败请求。

5. 验证

开一个 Chat，问一句「这个文件是做什么的」。能返回就通了。 再试一次 Composer（多文件改动），确认工具调用没问题。

三个容易被忽略的细节

1. 隐私模式与数据流向

开了 Privacy Mode 只代表 Cursor 不拿你的代码训练它的模型。 走自定义 API 时，代码仍然会发到你的端点——那是另一层可见方， 和 Cursor 的隐私设置无关。想弄清这一层，看 中转方能看到什么。

2. 模型选择影响的不只是质量

Cursor 里换个模型，token 消耗可能差好几倍。Chat 用日常档、批量改动用机械档， 具体分档方式见 该用哪个模型。

3. 上下文自动附带

Cursor 会把打开的文件、光标附近的代码一并发送。账单涨得比预期快，常常是上下文重传， 不是模型贵。原因拆解见 Token 花得比预期快。

要不要用 Cursor 走中转

场景建议
只是偶尔用 Chat 问问题订阅额度通常够，不必折腾
重度用 Composer 改多文件走自己的 key 更可控，也更容易看清花费
团队多人走自己的 key 才能按人归属用量，见 两层 key
需要特定国产模型只能走自定义端点，Cursor 内置没有
