AI API 中转站怎么选？
6 条判断标准 + 5 个 60 秒验证动作

不怕贵，怕不透明。价签清楚的站，贵一点也能算账；价签模糊的站，便宜也可能吃亏。

一、先给结论：看这 6 条硬指标

维度要看的硬指标怎么验证
计费透明返回体是否给出 cache hit / miss 拆分发一个请求看 usage 字段
倍率公开分组倍率是否写在后台不是写在宣传页，是写在后台「可用渠道」
缓存单价缓存读是否显著低于正常输入常见 10%，15%~30% 要留神
协议覆盖同一 base_url 是否同时支持 OpenAI + Anthropic分别打 /v1/chat/completions 和 /v1/messages
账单颗粒度能否按请求看 token、延迟、实际扣费有没有明细导出
充值门槛起充金额、余额是否过期起充越低越安全
核心一条成本差异的大头不是标价，而是缓存计价方式。两个站标价差 20%，实测账单可能差 3 倍。

二、五个 60 秒验证动作（可直接复制）

动作 1：无 key 访问，必须返回 401

curl -s -o /dev/null -w "%{http_code}\n" https://你的中转站/v1/models
# 期望：401。返回 200 说明鉴权形同虚设；返回花哨错误页说明是套壳

动作 2：模型清单 vs 定价页是否对得上

curl -s https://你的中转站/v1/models -H "Authorization: Bearer $KEY" | head -c 800

动作 3：看 usage 有没有缓存拆分

# 关注响应里的这两个字段，没有就是黑盒计费：
#   prompt_cache_hit_tokens
#   prompt_cache_miss_tokens

动作 4：同一个 prompt 连发两次，第二次必须更便宜

这是最狠的验证项。缓存没生效，成本会差出 5~10 倍，而且账单上看不出来。把两次的 usage 和扣费金额对比，差额就是缓存真实生效的证据。

动作 5：Anthropic 协议单独测一遍

curl -s https://你的中转站/v1/messages \
  -H "x-api-key: $KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"claude-sonnet-4-5","max_tokens":16,
       "messages":[{"role":"user","content":"hi"}]}'

三、成本差在哪：一次真实调用的拆解

指标数值说明
prompt_tokens1,755总输入
prompt_cache_hit_tokens1,536（87.5%）走缓存读
prompt_cache_miss_tokens219按正常输入计价
completion_tokens20输出

编程类 Agent（Claude Code、Codex CLI）每一轮都在重发大段系统提示和文件上下文。当输入里 80%+ 走缓存命中时，缓存单价就成了账单的主导项。

这就解释了为什么「标价低」和「实际便宜」经常是两回事：

  • 标价低 + 缓存按全价算 → 实测反而贵
  • 标价中等 + 缓存命中率高 → 实测便宜一大截

五、避坑清单

  1. 别大额充值。这行业不稳定，充够一个月用量就行。
  2. 警惕异常低价。明显低于成本价的，大概率拿便宜模型顶替高价模型。
  3. 看缓存单价。收 30% 缓存费的和收 10% 的，一个月能差出一倍账单。
  4. 要明细账单。出问题时能查到具体哪一笔，比客服态度重要。
  5. 先小额试。1 元起充的站优先。

六、常见问题

Q：换站之后 Claude Code 报模型不存在？

模型名要跟实际能调的清单一致。先 curl /v1/models 拿到确切名字再填。

Q：Codex CLI 提示 base_url 格式错误？

Codex CLI 要求带 /v1，Claude Code 要求不带 /v1。这是最常见的坑。

Q：两边的 key 能混用吗？

不能。key 是站点级别的，换站必须换 key。

Q：担心跑路怎么办？

小额试。先充最低额度跑两周，够用再续。
