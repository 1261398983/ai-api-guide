AI 编程工具接中转站：十款工具的配置位置与片段

2026-10-24 · 每个工具给「配置文件在哪 + 改哪几行」，不给截图

同一个中转端点，不同工具的接法差别很大：有的读环境变量，有的写 JSON，有的只能在图形界面里点。这篇按工具逐个列，找你要的那一款即可。

先确认一件事：多数 SDK 会自己拼接路径，所以 base_url 一般只写到 https://api.97wl.cc/v1；但少数工具要你填完整端点。报 404 时优先怀疑这一点。

一、命令行类

Claude Code

读环境变量，不需要配置文件。

export ANTHROPIC_BASE_URL="https://api.97wl.cc"
export ANTHROPIC_AUTH_TOKEN="sk-你的key"

Windows PowerShell：

$env:ANTHROPIC_BASE_URL="https://api.97wl.cc"
$env:ANTHROPIC_AUTH_TOKEN="sk-你的key"

注意变量名是 AUTH_TOKEN，不是 ANTHROPIC_API_KEY——写成后者 Claude Code 会忽略，然后用你自己的官方 key 去连官方，报 401 时很难想到是这里。

Gemini CLI

官方版只认 Google 协议，不能直接指向 OpenAI 兼容端点。支持自定义网关的版本用：

export GOOGLE_GEMINI_BASE_URL="https://api.97wl.cc"
export GEMINI_API_KEY="sk-你的key"

如果你的版本不认这个变量，说明它不支持第三方网关——这时要么用官方 key，要么在网关侧确认是否提供 Gemini 原生协议。

Aider

~/.aider.conf.yml 或项目内 .aider.conf.yml：

openai-api-base: https://api.97wl.cc/v1
openai-api-key: sk-你的key
model: gpt-5.1

或者用环境变量（四件套，缺一个就会退回官方）：

export OPENAI_API_BASE="https://api.97wl.cc/v1"
export OPENAI_API_KEY="sk-你的key"
export AIDER_MODEL="gpt-5.1"
export AIDER_WEAK_MODEL="gpt-5.1-mini"

Aider 还有个坑：它默认会读 OPENAI_ORG_ID，如果你的环境里残留了这个变量，请求会带错租户头，报 401。

OpenCode

~/.config/opencode/opencode.json：

{
  "provider": {
    "relay": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://api.97wl.cc/v1",
        "apiKey": "sk-你的key"
      },
      "models": { "gpt-5.1": {}, "claude-sonnet-4-5": {} }
    }
  },
  "model": "relay/gpt-5.1"
}

模型名要和你网关实际提供的完全一致，写错会报「model not found」而不是 404，容易误判成 key 问题。

Codex CLI

~/.codex/config.toml：

[model_providers.relay]
name = "RELAY X"
base_url = "https://api.97wl.cc/v1"
env_key = "RELAY_API_KEY"

[profiles.main]
model = "gpt-5.1"
model_provider = "relay"

二、编辑器与 IDE

Cursor

设置 → Models → Override OpenAI Base URL，填 https://api.97wl.cc/v1，key 填在同页。仅对「自带 key」模式生效，订阅模式走的是 Cursor 自己的后端。

Windsurf

设置里找 Cascade → Provider → 自定义 OpenAI 兼容端点。填 base URL 与 key 后需要重启窗口，否则新配置不加载。

Zed

~/.config/zed/settings.json：

"language_models": {
  "openai": {
    "api_url": "https://api.97wl.cc/v1",
    "available_models": [{ "name": "gpt-5.1", "max_tokens": 128000 }]
  }
}

JetBrains AI Assistant

原生只支持 JetBrains 自家后端。要用中转，走插件：装 Continue 或 Proxy AI，在插件里配端点，而不是在 IDE 设置里配。

三、VS Code 插件

Cline

设置 → API Provider 选 OpenAI Compatible → Base URL https://api.97wl.cc/v1 → API Key → Model ID 手填。填完点一次「Test」，能返回模型列表才算通。

Roo Code

与 Cline 同一套界面逻辑，但多一个 Model Info：需要手动填上下文长度和价格，否则用量统计会算错（不影响调用）。

Continue

~/.continue/config.json（新版是 config.yaml）：

{
  "models": [{
    "title": "RELAY X",
    "provider": "openai",
    "model": "gpt-5.1",
    "apiBase": "https://api.97wl.cc/v1",
    "apiKey": "sk-你的key"
  }]
}

四、桌面客户端

Cherry Studio / LobeChat / NextChat / ChatBox 都是同一类：设置里找「自定义 OpenAI」，填 API 地址（https://api.97wl.cc/v1）、密钥、模型名三项。Cherry Studio 额外支持 Anthropic 协议，切到那一栏时地址不带 /v1。

五、配置完连不上时的排查顺序

现象先查这个
一直转圈DNS 是否解析（nslookup api.97wl.cc）
401变量名是否写错（AUTH_TOKEN vs API_KEY）
404base_url 是否多写或少写了 /v1
model not found模型名与网关提供的是否完全一致
429看响应头 retry-after，按秒退避

更细的分层排查见 连不上？四层排查。
