流式输出卡住不动？中转 SSE 逐层排查

2026-10-24 · 症状 → 分层 → 每条给判别命令

流式失效有三种典型表现，原因完全不同：

表现大概率原因
开了 stream:true，但一次性返回全部某一层缓冲（nginx / CDN / 客户端读法）
开始正常，吐到一半停住代理超时（Cloudflare 100s、网关 read timeout）
先静默几秒，然后瞬间全部出现假流式：服务端先聚合再逐字吐

一、先确认客户端真的在流式读

curl 基准测试

curl -N -X POST https://api.97wl.cc/v1/chat/completions \
  -H "Authorization: Bearer sk-你的key" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.1","stream":true,"messages":[{"role":"user","content":"数到二十"}]}' \
  | while IFS= read -r line; do printf "%s %s\n" "$(date +%s.%N)" "$line"; done

-N 关闭 curl 自身的缓冲，这很关键——不加 -N 会把流攒成整块，让你误判。

看时间戳：

时间戳形态结论
首块很快，后续间隔几十毫秒链路正常，问题在你的客户端
首块就很慢，之后均匀上游慢，不是流式问题
静默数秒后全部块同时到达中间层缓冲，或服务端假流式

代码里常见的两个错误

// ❌ axios 默认会把整个响应读完再给你
const res = await axios.post(url, body)

// ✅ 用 responseType: 'stream'（Node）/ fetch + reader（浏览器）
const res = await fetch(url, { method:'POST', headers, body: JSON.stringify(body) })
const reader = res.body.getReader()
const dec = new TextDecoder()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  process.stdout.write(dec.decode(value, { stream: true }))
}

Python 侧对应的是 requests(..., stream=True) + iter_lines()；忘了 stream=True 就会一次性拿到全文。

二、服务端中间层：缓冲

nginx

默认 proxy_buffering on，会把上游数据攒够一个 buffer 再转发。流式接口必须关掉：

location /v1/ {
    proxy_pass http://upstream;
    proxy_http_version 1.1;

    proxy_buffering off;              # 关键
    proxy_cache off;
    proxy_set_header Connection "";
    chunked_transfer_encoding on;

    proxy_read_timeout 300s;          # 长回复别用默认 60s
    proxy_send_timeout 300s;
}
注意：proxy_buffering off 只对 /v1/ 这类转发路径加，不要加在整站上——静态资源开缓冲反而更快。

Cloudflare

  • 免费版单请求响应上限 100 秒，长回复会被切断且通常不报错
  • 默认对 HTML 缓存与压缩，SSE 需要确认响应头是 text/event-stream 且 Cache-Control: no-cache
  • 某些压缩（Brotli）会在服务端聚合后再发，等于消灭流式

其他常见中间件

组件要检查的点
宝塔 / Nginx Proxy Manager默认开的 gzip 与 buffering
ApacheSetEnv proxy-sendchunked 1、关闭 mod_deflate
Caddy默认已支持流式，主要看 encode 指令
Node 反代（http-proxy）需 selfHandleResponse 或直接 pipe 不缓冲

三、上游与协议层

响应头对不对

Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no

最后一行是给 nginx 看的覆盖指令。有些网关通过它单独关闭缓冲，比改全局配置安全。

Anthropic 协议的差异

Anthropic 的流式事件是分类型的（message_start / content_block_delta / message_stop），解析方式和 OpenAI 的 data: {...} 不同。用 OpenAI SDK 去打 Anthropic 端点会收不到 delta，表现像「卡住」。

四、判断是不是假流式

真流式：首 token 延迟（TTFT）明显小于总时长，且块间隔稳定。
假流式：服务端等上游生成完，再把内容按字切开发给你——总时长不变，但首块延迟 ≈ 总时长。

# 直接对比两个数字
总耗时：curl -o /dev/null -s -w "%{time_total}\n" ...
首块时间：上面那条带时间戳的命令，看第一个 data 行的时间

若两者几乎相等，就是假流式。这不是「坏了」，但意味着你失去了流式在体验上的全部好处。

五、排查顺序（照这个顺序做，不要跳）

  1. curl -N 打一次，确认服务端本身是否流式
  2. 若服务端正常 → 换客户端写法（fetch reader / stream=True）
  3. 若服务端也不流 → 查 Content-Type 与 X-Accel-Buffering
  4. 仍不流 → 查中间层 buffering 与压缩
  5. 流到一半断 → 查超时（Cloudflare 100s、nginx read_timeout）
